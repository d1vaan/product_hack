# Демо-стенд: подсказка выгодного момента для трансграничного перевода

Публичный веб-стенд. Посторонний человек открывает ссылку и за 3 минуты
проживает клиентский путь фичи: получает пуш → открывает экран перевода →
попадает в том числе в ситуацию «момент уже изменился» → доводит перевод до
конца. Стенд **не** считает и не показывает метрики отклика.

Собран по документам `dev/tz-demo-stand-v0.1.md`, `dev/user-path-v2.md`,
`dev/analiz-stend-triggery.md`.

---

## Что внутри

```
proxy (Caddy)  ──►  web (React, статика)
               ──►  api (FastAPI)  ──HTTP(опц.)──►  ml (контейнер модели)
                         │
                         └── data/*.csv, *.json   (без БД)
```

- **Базы данных нет.** Курсы и сигналы — файлы в репозитории. Резервы и
  события — в памяти процесса + append в `logs/events.jsonl`. Перезапуск
  контейнера обнуляет демо-сессии, это осознанно.
- **Источник сигналов переключается** переменной `ML_URL`. Пусто →
  `data/signals.json`. Задан → бэкенд ходит по HTTP, при ошибке/таймауте 2 с
  откатывается на файл и показывает это в `/api/health`. Стенд работает без
  контейнера модели.
- **Симулированное время.** Стенд живёт на исторических датах (`sim_date`).
  Реальное время — только в метках лога.

Три режима переключаются в тёмной служебной шапке:

| Режим | Что видно |
|---|---|
| **Демо** | только макет приложения — то, что видит жюри |
| **Разбор** | макет + панель: пульт сценария, крутилки, лента событий, библиотека текстов, источник сигналов |
| **Данные** | график курса со сработками, таблица сигналов, плашка ограничений |

Любой прогон воспроизводим по ссылке: `/?scenario=S2` или
`/?scenario=S2&mode=review&mechanic=A&delay=360`.

## Локальный запуск для разработки

Бэкенд:

```bash
cd api
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cd ..
uvicorn api.main:app --reload --port 8000
```

Фронтенд (в отдельном терминале):

```bash
cd web
npm install
npm run dev        # http://localhost:5173, /api проксируется на :8000
```

Прогон инвариантов (сценарии, тексты, резерв, запрет заглядывания вперёд):

```bash
python -m api.selftest
```

## Данные

| Файл | Что |
|---|---|
| `data/rates.csv` | дневной ряд курсов, `date,corridor,rate,is_stale`. `rate` — рублей за 1 единицу валюты получателя, номинал нормирован на этапе подготовки |
| `data/signals.json` | ответ модели, предпосчитанный по истории. Модель отдаёт факты и `scenario_code`, не текст |
| `data/personas.json` | 5 портретов с поведенческими параметрами |
| `data/scenarios.json` | сценарии S1–S7, поле `expected_state` — это тест, а не логика |
| `data/texts.json` | библиотека формулировок: `push` / `plaque` / `forbidden` / `why_forbidden` |

### Перегенерация данных

Оффлайн (детерминированный синтетический ряд, даты сценариев уже выставлены):

```bash
python3 tools/gen_data.py
```

Реальная выгрузка ЦБ РФ (нужна сеть; проверяет `diff()` по номиналу):

```bash
python3 tools/prepare_rates.py --from 2021-01-01 --to 2026-08-31
```

> `prepare_rates.py` обновляет только `rates.csv`. `signals.json` под новый ряд
> отдаёт ML-команда либо пересобирает `gen_data.py`.

## Контракт ручки модели (интерфейс между командами)

Модель — отдельный контейнер, реализует **два** метода. Стенд не знает, что
внутри. Скелет — в `ml/`.

```
GET /health   → {"status":"ok","model_version":"rules-level-v0.3"}
GET /signals?as_of=2026-06-15&corridors=RUB_TJS,RUB_UZS
```

```json
{
  "as_of": "2026-06-15",
  "model_version": "rules-level-v0.3",
  "signals": [{
    "date": "2026-06-15", "corridor": "RUB_TJS",
    "indicator": "level_p10", "direction": "favorable", "speed": "slow",
    "strength": 0.82, "scenario_code": "LEVEL_LOW",
    "facts": {"rate": 0.10883, "percentile": 12, "window_days": 90,
              "streak_days": 4, "change_bp": -145}
  }]
}
```

Правила: модель отдаёт **факты и `scenario_code`**, не текст, не рекомендацию,
не вероятность. `scenario_code` ∈ `MOMENTUM_DOWN, LEVEL_LOW, REVERSAL_UP,
SEASONAL, NEUTRAL, ML_MOMENT`. Ответ на `as_of=T` не зависит от данных после T
(проверяется двумя вызовами на пересекающихся датах).

## Рабочие ML-сервисы (`ml/`)

Три контейнера, поднятых из настоящего кода ML-команды (git submodule
`ml/upstream` → `AI_Product_Hack_trigger_model`, зафиксирован, **не
модифицируется**):

| Сервис | Что делает | Эндпоинты |
|---|---|---|
| **parser** | Парсер котировок валютных пар ЦБ РФ (`src/cbr_loader.py`) | `/health`, `/pairs`, `/rates?corridor=`, `/rates/wide` |
| **moment-model** | ML-модель выгодного момента: 100 rule+ML движков `GOOD_NOW`/`WINDOW_CLOSING` × горизонты 1/3/5/10/20 × 5 валют, walk-forward с переобучением | `/health`, `/registry`, `/engine-signals?as_of=` |
| **push-model** | ML-модель «какой сигнал в пуш»: логистическая метамодель + частотная политика (cooldown 3 дн., ≤2 / 7 дн.). Реализует контракт стенда выше | `/health`, `/signals?as_of=`, `/push-events`, `/decisions?as_of=` |

Плюс одноразовый `ml-warmup` — прогоняет полный production-конвейер
(`ml/upstream/notebooks/prod_pipline.ipynb`), кэширует артефакты в docker-том
`ml_data`, переписывает `data/rates.csv` реальными курсами ЦБ и `data/scenarios.json`
/ `data/signals.json` на реальные срабатывания модели (синтетику → `data/*.synthetic.*`).

```bash
cp .env.example .env
docker compose -f docker-compose.yml -f docker-compose.ml.yml --profile ml up --build
```

Первый старт: `ml-warmup` считает **~11–15 мин** (полный walk-forward replay с
2020). Дальше — мгновенно (артефакты в томе). Ускорить: `ML_REPLAY_FROM=2024-01-01`.

Стенд при этом берёт курсы у `parser`, сигналы у `push-model`, сырой поток
движков у `moment-model`; при недоступности любого — молчаливый откат на
`data/*`, факт отката виден в `/api/health` (`signals_source`, `rates_source`,
`ml_services`). В UI: режим **Данные** → блок «ML-конвейер».

Подробности — `ml/README.md`.

## Деплой на VPS

### 1. Требования к серверу

- 1–2 vCPU, 2 ГБ RAM, Ubuntu 22.04+
- Docker Engine + Compose plugin

### 2. Установка Docker (если ещё нет)

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker
```

### 3. Запуск

```bash
git clone <repo> stand && cd stand
cp .env.example .env
# при необходимости отредактируйте .env
docker compose up -d --build
```

### 4. Фаервол

```bash
sudo ufw allow 80
sudo ufw allow 443
```

### 5. Домен

- Без домена: оставьте `DOMAIN=` пустым — стенд на `http://<IP>`.
- С доменом: заведите A-запись на IP сервера, впишите `DOMAIN=stand.example.com`
  в `.env`, `docker compose up -d`. Caddy сам получит TLS-сертификат.

### 6. Подключение модели

```bash
# в .env:
ML_URL=http://ml:8000
docker compose --profile with-ml up -d --build
```

Проверка: в `/api/health` поле `signals_source.active` станет `http`.
Остановите контейнер `ml` — стенд не упадёт, источник вернётся в `file`.

### 7. Эксплуатация

```bash
docker compose logs -f api           # логи бэкенда
docker compose logs -f proxy         # логи Caddy / TLS
cat logs/events.jsonl                 # лог событий стенда
docker compose pull && docker compose up -d --build   # обновление версии
docker compose down                  # остановка
git checkout <старый-тег> && docker compose up -d --build   # откат
```

### 8. Проверка работоспособности

```bash
curl -s http://localhost/api/health | jq
```

Ожидаемо: `status: "ok"`, `signals_source.active` = `file` или `http`,
`dates_available` с диапазоном ряда, блок `params` с порогами.

## Проверочный список приёмки

- [ ] Ссылка открывается с телефона и с ноутбука, тело страницы не скроллится вбок.
- [ ] Сценарии S1 (OK), S2 (DRIFT), S5 (NEUTRAL) проходятся от пуша до успеха без ошибок в консоли.
- [ ] Панель разбора показывает, почему пуш отправлен и почему подавлен.
- [ ] `FEATURE_RESERVE=false` не ломает базовый путь.
- [ ] Отключение `ml` не ломает стенд, `/api/health` показывает `file`.
- [ ] В клиентском макете нет ни одного числа без источника; числа-параметры живут только в панели с пометкой.
- [ ] Ни на одном экране нет вердикта «выгодно/невыгодно» и глаголов будущего времени.
- [ ] Плашка сигнала имеет одинаковую заливку во всех четырёх состояниях; зелёного и красного в ней нет.
- [ ] Служебная шапка стенда визуально не спутывается с интерфейсом банка.
- [ ] `design/screenshots/` заполнен эталонными экранами; макет положен рядом и совпадает по раскладке, радиусам, высотам полей и типографике.

## Что стенд доказывает и чего не доказывает

**Доказывает:** механика встраивается в существующий путь перевода;
для ситуации «момент изменился» есть внятный ответ, ведущий себя достойно в
плохом сценарии; тексты проходят рамку комплаенса; сигнальный слой отделён от
интерфейса контрактом и заменяем.

**Не доказывает (и не должен):** конверсию, инкрементальный объём,
каннибализацию — это меряет пилот; точность модели — её меряет бэктест;
готовность клиента сдвинуть день перевода.
