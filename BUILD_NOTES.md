# Заметки по сборке — что сделано, что принято по умолчанию, что проверено

## Принятые решения (открытые вопросы ТЗ)

| Вопрос | Решение в этой сборке | Как поменять |
|---|---|---|
| Домен или IP | По IP, `DOMAIN` пуст. Caddy слушает `:80` | вписать `DOMAIN=` в `.env` |
| Сколько коридоров | Все пять (TJS, UZS, KGS, AMD, KZT). Сценарии живут на TJS/UZS/KGS | добавить сценарии в `data/scenarios.json` |
| `signals.json` первой версии | Синтетический, детерминированный, из `tools/gen_data.py`. Даты сценариев подогнаны под нужные состояния | заменить файлом от ML-команды, форма совпадает с контрактом |
| Ряд курсов | Синтетический (`gen_data.py`), ~2 года, медианный размах внутри месяца ≈ 5–6% | `tools/prepare_rates.py` тянет реальную выгрузку ЦБ |
| Механика DRIFT по умолчанию | **C** (дельта + контекст), переключатель A/B/C в панели | крутилка «Механика подачи DRIFT» |
| S7 (вето получателя) | Реализован как опциональный экран, флаг `FEATURE_RECIPIENT_LIMIT` | `FEATURE_RECIPIENT_LIMIT=false` |
| Скриншоты приложения | `design/screenshots/` пуст, лежит инструкция. Токены сняты «на глаз» по описанию из ТЗ §9.6 | положить PNG, уточнить `web/tailwind.config.js` пипеткой |

## Соответствие ТЗ

- Архитектура: `proxy` (Caddy) + `web` (React/Vite статика через nginx) + `api`
  (FastAPI/pandas, без БД) + опциональный `ml` (профиль `with-ml`).
- Источник сигналов: `ML_URL` пуст → `data/signals.json`; задан → HTTP с
  откатом на файл при ошибке/таймауте 2 с, факт отката в `/api/health`.
- Симулированное время: `sim_date` + `sim_minutes`, кодируются в query-строке.
  «+1 день» в панели сдвигает дату на следующий торговый день и переоценивает
  резервы (ленивая переоценка при чтении).
- Состояния экрана `OK / DRIFT / BETTER / NEUTRAL` по правилам ТЗ §8.2; порог
  DRIFT — крутилка. Плашка — один компонент, одинаковая заливка во всех
  состояниях, различие только иконкой и текстом; зелёного/красного нет.
- Тексты — только подстановка фактов из `texts.json` в утверждённые шаблоны;
  если факта нет — текст не рендерится. У каждого кода хранится запрещённый
  двойник и причина, видно в панели.
- Резерв: машина состояний `ACTIVE → EXECUTED | CANCELLED | EXPIRED |
  SUPERSEDED`, TTL 7 дней, при истечении разблокировка (не автоисполнение),
  чекбокс `fallback_send_on_expiry` по умолчанию выключен. Весь блок за флагом
  `FEATURE_RESERVE`; при `false` базовый путь полностью рабочий.
- Лог событий → `logs/events.jsonl`, отдаётся в панель. ПДн не собираются,
  сессия анонимна (`session_id` — случайная строка с фронта).
- Экраны: B1 пуш-тост, B2 главная, B2a список стран, B3 перевод с плашкой и
  строкой «получатель получит», B4 подтверждение (без строки комиссии),
  B5 успех, B6 настройки уведомлений; R1–R5 резерв; экран данных с графиком.

## Что проверено

- `tools/gen_data.py` отрабатывает, `rates.csv` (3650 строк) и `signals.json`
  консистентны, номинал не скачет.
- Автономная реплика логики evaluate прогнана по всем 7 сценариям:
  `expected_state` совпадает с фактом, все плашки рендерятся без дыр,
  S2 даёт delta_bp ≈ 45 и −824 смн у получателя, S5 даёт NEUTRAL.
- `python -m py_compile` по всему бэкенду и tools — чисто.
- `api/selftest.py` — прогон инвариантов внутри контейнера/venv
  (`python -m api.selftest`).

## Что НЕ проверено на этой машине (нет Node и Docker)

- `npm install && npm run build` фронтенда — код написан по стандартным
  паттернам Vite/React 18/TS, но первый билд может выдать мелкие замечания
  (обычно — неиспользуемые импорты; `noUnusedLocals` уже выключен).
- `docker compose up --build` — конфиги написаны по спецификации, но не
  прогонялись. Первый деплой стоит делать по README пошагово.

## Первый запуск после клонирования

```bash
cp .env.example .env
docker compose up -d --build
curl -s http://localhost/api/health | jq      # ожидаем status: ok
```

Открыть `http://localhost/?scenario=S2&mode=review` — это сердце кейса
(«момент изменился»), сразу в режиме разбора.
